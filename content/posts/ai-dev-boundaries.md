AI 编码助手越来越能干：它能读写文件、执行命令、提交代码，甚至登录服务器。能力越大，"做多了"的风险也越大：顺手重构了你没让它动的模块，为了让测试通过改掉了断言，或者在你只想要一个方案时直接改了十几个文件。

给 AI 设置开发边界，本质上和给新同事讲清楚"哪些能自己决定、哪些必须先问"是一回事。这篇文章从**授权、范围、停止条件**三个维度讲我的做法。

## 一、授权边界：按操作的风险分级

不同操作的后果差别很大，授权也应该分级：

| 级别 | 操作 | 规则 |
| --- | --- | --- |
| 自由执行 | 读文件、搜索代码、查看 diff 和日志 | 调查范围内直接做 |
| 按请求执行 | 修改用户点名的文件和功能 | 用户提出修改需求后直接改 |
| 必须确认 | 删除文件、改数据库、提交推送、外部系统写入、付费操作 | 说明影响后等待明确同意 |

关键是区分**请求的类型**：

- 用户问"这里为什么报错"，是诊断请求，只应该调查并报告，不应该直接改代码。
- 用户说"帮我修复"，才是修改请求。
- 用户说"先给方案"，就交付方案后停下来，等确认再动手。

写进规则里大概是这样：

```markdown
- 回答、解释、评审、诊断或规划请求：检查材料并报告结果，不写入文件
- 修改请求：目标和范围明确时直接完成，不停留在方案
- 删除、提交、推送、外部系统写入：执行前取得明确授权
```

## 二、范围边界：最小变更集

AI 很容易"顺手"做一些看起来有益的事：统一一下格式、重命名几个变量、给旁边的函数也加上错误处理。每一个单独看都合理，加起来就是一个难以审查的巨大 diff。

我要求 AI 遵循**最小变更原则**：

- 只修改用户点名的文件、符号和行为，以及被证明直接相关的代码。
- 不顺手调整格式、命名、依赖或无关文件。
- 发现确实需要扩大范围时，停下来说明原因，而不是自行扩展。
- 保留现有功能和错误语义，不删除没被要求删除的逻辑。

一个容易忽略的点是**工作区里已有的改动**。用户可能有未提交的代码，AI 不应该为了"干净"去回退或覆盖它们。

## 三、信息收集边界：查到够用就停

调查也需要边界。没有边界的 AI 会为了"更确定"不断扩大搜索：读完调用方读消费者，读完消费者翻 Git 历史。这既浪费 Token，也会让结论迟迟不能交付。

几条实用规则：

1. 从用户指定的文件、错误和路径开始。
2. 扩大范围必须有已读材料中的直接线索，"顺便检查"不算理由。
3. 连续两次搜索都没有带来新信息，就停止这个方向。
4. 能用精确路径或符号定位时，不做全仓库搜索。

对于故障诊断，有一个很好用的停止标准：**能串起"症状 → 输入 → 错误位置 → 修复路径"，就停止取证，交付结论。**

## 四、停止条件：明确什么叫"完成"

AI 不知道什么时候停，常常表现为两种极端：要么没验证就宣布完成，要么完成了还在不停"再检查一遍"。所以要把完成条件写清楚：

```markdown
任务完成意味着：
- 已交付用户请求的结果，范围与授权一致
- 关键结论可以由文件、日志、命令输出复核
- 已完成与范围相称的验证，并说明未覆盖的部分

达到这些条件后立即交付，不追加额外调查。
```

被阻塞时也要有明确的出口：说明哪件事没完成、为什么、需要用户做什么决定，而不是把未完成的任务包装成完成。

## 五、技术手段：别只靠提示词

提示词是软约束，关键边界最好有硬约束兜底：

- **只读模式**：很多 Agent 工具支持计划模式或只读模式，调查和方案阶段不给写权限。
- **工具白名单**：只开放任务需要的工具，比如审查任务只给读文件和搜索。
- **命令拦截**：对 `rm -rf`、`git push --force`、`DROP TABLE` 这类命令设置确认或直接拒绝。
- **独立凭证**：AI 使用的数据库账号、云服务密钥只给最小权限，生产环境用只读账号。
- **Git 作为安全网**：在独立分支或 worktree 中工作，所有改动都能通过 diff 审查、随时回退。

```bash
# 为 AI 任务单独开一个工作目录，不影响主工作区
git worktree add ../blog-ai-task -b ai/image-upload
```

## 六、子 Agent 的边界

把任务拆给多个子 Agent 并行时，边界更要清楚：

- 子 Agent 默认只读，只返回证据和结论；写文件、做决策由主线程负责。
- 每个子任务只有一个问题域，写明背景、范围、输出格式。
- 存在依赖关系的任务按顺序处理，不要并行修改同一个文件。

## 小结

一份好的边界规则，读起来应该像给靠谱同事的工作说明：

- 什么可以直接做，什么要先问；
- 改动只到哪里为止；
- 查到什么程度就该停；
- 怎样算完成，没完成时怎么汇报。

把这些写进项目根目录的 `AGENTS.md` 或对应工具的规则文件里，AI 的行为会稳定可预期得多。
